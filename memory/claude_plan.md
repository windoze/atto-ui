# 执行计划

## 约束

- 以 `TODO.md` 为任务顺序和完成状态的唯一依据。
- 本次只完成第一个未在标题中标记 `[DONE]` 的任务，然后停止。
- 如果遇到阻塞当前任务的缺陷、测试失败或缺失能力，优先修复；无法直接修复时，将最小必要前置任务插入 `TODO.md`，提交后停止。
- 任务完成后必须更新 `TODO.md` 的标题和完成记录，并提交所有相关变更。
- 常规进度不更新 `PLAN.md`，除非阶段级计划或依赖发生变化。

## 步骤

1. 读取 `TODO.md`，确认第一个标题未带 `[DONE]` 的任务及其验证要求。
2. 查看最近提交，只有当其明确提到与当前任务直接相关的未完成事项时，纳入本次任务或在 `TODO.md` 中登记为前置任务。
3. 检查当前工作区状态，避免覆盖用户或其他代理的未提交改动。
4. 根据任务要求阅读相关代码和测试，确定最小正确修改范围。
5. 实施任务；如果发现当前任务被未跟踪的前置缺陷阻塞，则更新 `TODO.md` 并提交后停止。
6. 按要求先运行 `cargo fmt`，再运行 `cargo clippy --all-targets -- -D warnings`，最后运行相关或完整测试；若有失败且未明确排期，修复或登记为前置任务。
7. 更新 `TODO.md`：在完成任务标题前加 `[DONE]`，补充完成记录和验证结果。
8. 更新本文件记录关键进展。
9. 复查 `git diff`、`git status` 和最近提交，提交本次所有相关变更。
10. 停止，不继续处理后续任务。
