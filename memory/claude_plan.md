# 执行计划

## 当前约束

- 以 `TODO.md` 为任务顺序和完成状态的唯一依据。
- 只完成第一个未标记 `[DONE]` 的任务，然后停止。
- 不做开放式历史问题扫描；只处理当前任务范围内或阻塞当前任务的问题。
- 不使用规避实现；如果发现阻塞性的缺失功能或规格不匹配，先在 `TODO.md` 中加入最小必要前置任务并提交后停止。
- 完成后必须更新 `TODO.md` 的任务标题为 `[DONE]` 并填写完成记录，必要时才更新 `PLAN.md`。
- 提交前按要求运行 `cargo fmt`、`cargo clippy --all-targets -- -D warnings`，再运行相关或完整测试；如仅文档变更且无代码变更，可复用上次绿色结果并说明。

## 步骤

1. 读取 `TODO.md`，按文件顺序定位第一个标题未带 `[DONE]` 的任务。
2. 查看最新提交信息，只有在它明确提到与当前任务直接相关的未完成事项时，才将其纳入当前任务或作为前置任务记录到 `TODO.md`。
3. 阅读当前任务涉及的代码、测试和文档，确认验收标准与依赖。
4. 实现当前任务的最小正确变更，不修改无关用户改动。
5. 增加或调整必要测试，避免夹具或测试专用规避。
6. 运行格式化、lint 和测试验证；若发现未安排的测试或夹具失败，修复或在 `TODO.md` 中排入正确位置。
7. 更新 `TODO.md`，将当前任务标题加上 `[DONE]` 并补充完成记录；仅当阶段级计划改变时更新 `PLAN.md`。
8. 检查 `git status`、`git diff` 和最近提交，确认只提交本次相关改动。
9. 创建清晰的 git 提交。
10. 停止，不继续处理下一个任务。
